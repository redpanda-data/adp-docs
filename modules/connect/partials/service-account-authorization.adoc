== Service account authorization

When you create an MCP server or AI agent, Agentic Data Plane automatically creates a service account to authenticate requests to Agentic Data Plane resources. The service account is created with the following:

*Name*: Prepopulated from the resource name. The service account's client ID takes the form `serviceaccounts/<resource-name>`, and its principal is `<resource-name>@iam.serviceaccounts.<dns-zone>`, where `<dns-zone>` is your environment's DNS zone. For example, an agent named `my-agent` gets the client ID `serviceaccounts/my-agent`. You can customize the name during creation.

*Role binding*: Cluster scope with Writer role for the cluster where you created the resource. This allows the resource to read and write data, manage topics, and access cluster resources.

That binding covers Kafka and cluster resources only. It grants nothing in Agentic Data Plane, so what the resource may do to agents, MCP servers, and LLM providers comes from xref:control:access-policies.adoc[access policies] instead. For an agent, author those on its *Permissions* tab, where the principal is locked to the agent's service account.

=== Manage service accounts

You can view and manage service accounts created for MCP servers and AI agents at the organization level in *Organization IAM* > *Service accounts*. This page shows additional details not visible during creation:

[cols="1,2", options="header"]
|===
|Field |Description

|Client ID
|Unique identifier for OAuth2 authentication

|Description
|Optional description of the service account

|Created at
|Timestamp when the service account was created

|Updated at
|Timestamp of the last modification
|===

From this page you can:

* Edit the service account name or description
* View and manage role bindings
* Rotate credentials
* Delete the service account

[NOTE]
====
Deleting a service account removes authentication for the associated MCP server or AI agent. The resource can no longer access cluster data.
====

=== Customize role bindings

This section covers the service account's Kafka and cluster access only. Its Agentic Data Plane access is governed by xref:control:access-policies.adoc[access policies], not by this role binding.

The default Writer role provides broad Kafka access suitable for most use cases. If you need more restrictive permissions:

. On the agent's *Connect* tab, click *Manage service accounts* to open *Organization IAM* > *Service accounts*.
. Find the service account for your resource.
. Edit the role bindings to use a more restrictive role or scope.

For more information about roles and permissions, see xref:cloud-data-platform:security:authorization/rbac/rbac.adoc[Role-based access control] or xref:cloud-data-platform:security:authorization/gbac/gbac.adoc[Group-based access control].
